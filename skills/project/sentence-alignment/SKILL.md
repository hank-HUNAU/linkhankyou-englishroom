# 句级音频↔文本对齐

把一段朗读/演讲音频与已知课文文本按"句"精准对齐，产出 逐句时间轴(TL)、每句 wav、词级点读时间(WORDS)，并保证点读归属正确。判准：**零串音、零丢词、零尾音腰斩、每个词都可高亮**。

## 何时调用

- 需要把音频按句子切成独立 wav + 时间轴
- 需要逐句/逐词点读高亮的时间戳
- 遇到 串句首词(句首词显示在上句高亮)、块界切入词、句尾辅音被腰斩 等对齐缺陷要修

## 核心判准

1. **零串音**：相邻句无声音交叠/串入。句界必须在静音谷底，而非语音上。
2. **零丢词**：句首词首音素、句末词尾音素(尤其摩擦音 /s/ /f/ /θ/、爆破 /p/ /t/ /k/ /b/)必须完整保留。
3. **零腰斩**：剪辑点落在真实语音上即腰斩。句尾须有足够静音盈余(ex: ≥40ms)。
4. **词点必亮**：前端做时间→词归属后，每个词的时间戳必须落在所属句块内，句首词不能钳进上一句。

## 管线（三层）

```
① ASR 粗锚   faster-whisper small.en  词级时间戳 + 句段粗定时
② 声学精修   帧能量 + 清/浊掩膜 → 真实语音首末 → 派生裁剪边界 → 每句 wav + TL
③ 归属钳制   前端词级贪心匹配 + clamp → 每个 .wd 的 data-t
```

### ① ASR 粗锚
- 用 `faster-whisper` 的 `word_timestamps=True`，纯 ASR 只提供"每个词大概在哪"，**不做句边界**。
- 领取 ASR 词级时间戳与句/段文本；有官方脚本时用它做 initial_prompt/强制对齐修正边界词。
- **不信任 ASR 的句边界**：其静音检测+语言模型合并的切点，在读得紧凑/连读处会漂移至下句首词，必须在第②层重切。

### ② 声学能量精修（句界核心）
- 解码为 22050Hz 单声道，逐 **5ms 帧** 计算 RMS(语音能量)、高频能、低频能。
- 自适应阈值取代固定 margin：阈值取 噪声底×系数 与 峰值×小系数 的较大者，能捡回低幅弱辅音(/h/ /ð/ /l/)。
- **第一遍**——以 ASR 区间为粗锚，在护栏窗口内找真实语音 onset/offset（`first_speech`/`last_speech`，补足词首爆破、捡回词尾摩擦音）。
- **第二遍**——派生裁剪边界：`start = onset − LEAD`、`end = offset + TAIL`，并以相邻句真实语音 ±5ms 为护栏夹逼；LEAD/TAIL 取 40~50ms 对称呼吸。
- **合并句**（无静音交接缝，如 /s/→/b/ 连续浊音）：对缝做**帧级能量下钻**(5ms 步长)，找上句尾音素收落点与下句首音素爆发点之间的能量谷底，取谷底为两句共享分界（`scan_signal.py` 首尾音素扫描联合裁决）。
- **1ms 级尾音复核**：对每条 clip 的 end_s 尾段做逐毫秒峰值剖面，标记 CLEAN(干净)/CLIP(距实音<12ms 边缘)/CUT(落在实音上,腰斩)/OVER(窗外还有高能瞬态)。只读复核，不自动改。

### ③ 前端归属钳制（点读依赖）
- 对每句可见词列表，用句窗 `TL[pg][si] ±0.25s` 过滤候选词级时间戳，遇 >0.30s 大隙截断为同句词集。
- **贪心语序匹配**：token 归一(去标点、小写)后逐词只在残余候选里向后找文本一致项，命中取该 ASR 词中点作为词时间；未命中项按比例插值回填。
- **clamp（关键，修串句首词）**：对落点越界词钳回句块区间——
  `fb = max(首块起点, TL句起点)`；`lb = 末块终点`；
  `out[j] < fb−0.02 → fb`；`out[j] > lb+0.02 → lb`。
  下限取 `max(块起点, TL 句起点)` 是为防止句首词时间戳早于句起点时被钳进上一句导致点读定位到上句。

## 质量控制闭环

1. **句界复核**：第②层尾音 1ms 剖面 + 首尾音素能量扫描，把 `首切·强/疑`、`尾切·强`、CUT 候选标出供人工放行——其中"贴合起音(But/And 等紧密衔接句)"与"低幅弱音前缘无大量静音"是健康信号，非截断，需结合首尾词类型裁决。
2. **内容双向校对**：把课文文本标准词表与"句窗内命中词"做序列对齐，查多词/缺词/序错(内容方向)；并核对句首词真实起点、句末词真实终点 vs 窗口(时间方向)。
3. **前端冒烟/端到端**：用无头浏览器加载页面，验证 all 页 TL/CHUNKS 齐备、0 JS error；对已知"串句首词"用例跑点读 e2e，断言 clamp 后该词时间戳落回块内且 `highlightAt` 命中断并点亮目标词。
4. **多目录/副本一致性**：同一数据源注入多个副本(原型/发布/部署)时，注入脚本需幂等(已同目标则跳过)，完成后做逐副本校验字节 SHA 对齐，避免三处漂移。

## 已知入坑(Tips)

- **ASR 词时间戳不可靠处**：词尾摩擦音、词首爆破音、句首/句末词易偏差甚至顺序颠倒；判断"串音/截断"必须回到信号层能量扫描，不能单凭 ASR 词时间戳。
- **不能信任单帧能量过阈**：检验 onset 需连续≥2 帧才判有效，否则单帧毛刺误判。
- **词内部塞音停顿**：/p//t//k/ 的成阻期会造成短暂低能，易被误判为句界；停顿<0.30s 且邻词首/尾为塞音时须判为塞音伪段(如 can|kick)，勿切。
- **句首/句末词易漏算**：首块前伸至 `min(句起始, 句内最小词中心−0.12s)`，末块后延至 `max(句结束, 句内最大词中心+0.12s)`。
- **前端归属键必须与数据一致**：多形态数据(内嵌字面量 vs 独立赋值)正确序要一致，键名用 `"p"+padStart(3,"0")` 统一，防 `p072` 丢 `p`。
- **浏览器缓存**：剪辑文件名不变时浏览器不刷新新音频，需给文件名加版本参数(?v=N)。

## 数据形态约定

- TL = 逐句 `[[start,end],...]`(秒，3 位小数)
- WORDS = 扁平词列表 `[start,end,text]`，前端按句窗过滤+文本匹配归属
- CHUNKS(意群) = 每句的子块 `[[s,e],...]`，clamp 以块界为准
- 词级来源用 ASR；句界/块界一律以声学能量为准，文本只做归属不回改时间。

## 端到端总流程（音频 → 注入多个部署副本）

给一份音频 + 已知课文文本，按下面顺序走完即产出对齐数据并落库到所有前端副本。每一阶段都要过对应的质量闸门后再进下一阶段。

```
S0  音频与文本就绪
 │
 ├─ S1  ASR 粗锚 ──────────→ draft(逐句文本+ASR词级时间)
 ├─ S2  声学精修定句界 ─────→ TL + 每句 wav
 ├─ S3  页面数据成形(可选) ─→ WORDS/CHUNKS/专名/译文 等
 ├─ S4  人工句中意群切分 ───→ 人工评审后的 CHUNKS
 └─ S5  归属钳制 + 注入多副本 → 全副本功能一致(点读归属正确)
```

### S0 准备
- 输入：整段朗读音频(可单/多音轨)、已知课文文本(逐句或全文)。
- 约定采样率与通道：解码统一到 22050Hz 单声道，便于帧能量分析。

### S1 ASR 粗锚
- 用 faster-whisper `word_timestamps=True` 取得 词级时间戳 + 句段文本，存为草稿 draft。
- 有官方脚本/文本时，用 initial_prompt 或强制对齐帮助修正边界词(如人名、地名)。
- **只作粗锚**，句边界不由 ASR 决定。

### S2 声学精修定句界
- 跑第②层两遍能量法(见上"管线 ②")：真实语音首末 → 派生带 LEAD/TAIL 的裁剪边界 → 写每句 wav + TL。
- 过闸门：逐句尾音 1ms 剖面全 CLEAN(无 CUT/OVER)，首尾能量扫描无真截断。
- 任何一处尾音 CUT 或整词串音/丢词，回到信号层(能量下钻取谷底)定点重切，勿整批重跑(避免覆盖手工修正)。

### S3 页面数据成形(可选)
- 由 TL/WORDS 推导：意群 CHUNKS(句内母语停顿+语法否决)、专名列表、标题起始、译文等，注入对应 DB 字段。
- 需注意数据形态差异：部分页数据内嵌在数据字面量里，部分页是独立赋值语句，统一键名后再操作。

### S4 人工句中意群切分(可选，但强烈建议)
- 独立技能 **`chunk-splitter`** 专门负责句内意群块切分：桌面应用(或 HTML 版)里渲染波形+句界+能量谷底线，人工点/拖/微调加块、逐句试听，快捷键操作。
- 人工放行后导出 `p{pg}_edit.json`（含 chunks），交 S5 导入。
- 本技能只保证句级对齐(零串音)；句内块归属的真实静音谷判定与快捷键交互逻辑以 `chunk-splitter` 为准。

### S5 归属钳制 + 注入多副本
- 前端依赖 ③ 归属钳制逻辑(clamp)保证点读归属正确。
- 用**幂等注入脚本**把 TL/WORDS/CHUNKS 写入所有前端副本(如 原型/发布/部署)：已同目标则跳过，无现成赋值则追加到数据字面量之后，避免 JSON 整体重排。
- **多副本一致性**是硬性闸门：注入后对每个副本做逐字节 SHA 校验，三副本必须完全一致；任一不同即视为回滚，再定位漂移源。

### 端到端的最终验收
- 无头浏览器加载每个副本的页面：所有页 TL/CHUNKS 齐全、0 JS error。
- 对已知"串句首词/块界切入词"用例跑点读 e2e：断言 clamp 后词时间戳落回所属句块，`highlightAt` 命中断并点亮目标词。
- 三副本 SHA 对齐。
- 全部通过才视为完成；任何失败带具体页/句/词定位回修，不自称完成。

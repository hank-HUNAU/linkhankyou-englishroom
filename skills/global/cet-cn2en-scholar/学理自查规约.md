# 学理自查规约 v1.7

> 用途：对「真题翻译学习材料」中**翻译策略(L1 宏观) / 翻译技巧(L3 微观)的学理标注做**一致性抽检——
> 校验"策略/技巧声称的学理手段"在译文中是否存在可检验的语言实证。
>
> 定位：**红旗机制（red-flag heuristic），非最终判定**。命中=通过（证据在译文可见）；未命中=需人工复核，不代表错误。
> 分工：本规约只管**译文侧**一致性抽检；**原文侧**处理（六类功能处理）自 v1.3 起见独立 `原文处理规约.md`，译文产出规则见 `译文产出规约.md`。
> 配套脚本：`_audit_scholar.py`（v1.3，本规约的机器可执行实现，二者校订同步）。

***

## 1. 目的与范围

- **要检的**：每句的 策略L1 与 技巧L3 文本中，若提及某一学理手段，则对应英文译文应体现该手段的**显性特征**。

- **不检的**：译文的忠实度、通顺度、风格、术语正误（那是其它质检环节）。

- **产出**：断言命中/未命中清单 + 统计；未实证项进入人工复核流。

## 3. 样板格式约定（脚本解析依据）

每句以 `### 句N` 开头，句内字段按 `译文产出规约.md` §1 固定行序；本规约（脚本）**只解析三行**：

```
- **译文**：<英文译文>
- **策略 L1**：<含学理触发词的说明>
- **技巧 L3**：<含学理触发词的说明>
```

> **关于 `原文处理` 行（可选，忽略）**：句题后允许出现 `- **原文处理**：…` 行（原文处理规约的输入侧决策行），但**被脚本忽略、不参与解析**。固定解析字段始终为上述三行（`译文 / 策略 L1 / 技巧 L3`），与 v1.3"只读三行、不解析原文处理行"的声明一致。

## 4. 运行方式

```bash

python _audit_scholar.py 文件.md ...     # 指定文件

```

## 5. 结果判定与人工复核流程

1. **绿色**：所有被触发断言均有译文实证。
2. **黄色（未实证）**：先判断是否**断言漏检**（如正则未覆盖"夹副词进行时 `is profoundly changing`"）→ 修断言，不擅改译文。
3. **红色（真实不一致）**：若译文确无该特征且策略确实声称 → 修译文或修策略标注，二选一，并记录原因。
4. **版本对齐**：报告头输出规约版本 + 运行日期，确保复评与当年规约一致。

## 5·附 录入须知：触发词—译文特征对齐（先验后写）

> **何以需要本附**：断言表是"**触发即评估**"机制——只要 `策略L1 + 技巧L3` 联合文本里**出现触发词**，脚本立即评估该断言。因此**写得对不对、译文有没有对应特征**，决定了抽检是"绿"还是"未实证"。历年批次（2018–2020 尤为集中）反复出现**同一类误触发**：标注用了某个学理名，但译文里实为**该断言特征词表之外的另一种结构**，导致"未实证"假阳性。本附即把这批经验固化为录入硬约束。

### 5·附1 高频误触发对照表（**录入前必查**）

| 触发词（写进 L1/L3 即评估） | 断言 | 断言**覆盖**的译文特征 | **不覆盖（最易误触发）** | 无对应特征时的推荐写法 |
|---|---|---|---|---|
| **分词** / 分词短语 | CL-03 | 逗号 + `-ing`；`with + its/their/a + N`；句首 `Following/Using/Hailed…`；`while + V-ing`；`by + V-ing`；`Through + V-ing` | **前置 V-ed 定语**（`Newly released statistics`）；**V-ed 后置修饰**（`policies aimed at …`）；**被动谓语核心**（`is planted`）；孤立过去分词 | 改写为「**前置 V-ed 定语**」「**V-ed 后置修饰**」「**被动谓语核心**（该 V-ed 式不在 CL-03 特征词表内，本句不计 CL-03）」——**三种写法均不含"分词"二字** |

### 5·附2 四条录入硬约束

1. **先验后写**：写任何一个触发词之前，**先在译文中定位对应特征**；定位不到，就不要写该触发词（改用 5·附1"推荐写法"列的表述）。
2. **负面说明也不得含触发词**：若需在句内声明"本句不计某断言"，**正文中不得出现该断言的触发词**——否则仍会被评估成未实证。正确做法是使用**不含触发词**的元语言描述（例：「该 V-ed 式不在 CL-03 特征词表内」而**非**"非分词结构，故不计 CL-03"）。
3. **夹副词先改词序**：CL-04/CL-08 允许 0–1 个插入词；遇多重副词，**优先在不改语义前提下调整词序**（把副词外移至句首或句末），仅在词序不可动时才改标注口径。
4. **修标注不擅改译文**（承 §5.3）：处置后在句内留「**一致性修复记录（日期 + 处置）**」，可回溯。

### 5·附3 抽检执行要求

- **每套产出后即跑**，至 **0 未实证**方可入库；**批量批次逐文件跑**（便于定位到卷次与句号），勿只在目录级跑一次。
- 报告头须含**规约版本 + 运行日期**；批次追溯表登记的"断言 N 项 · 0 未实证"以该次运行为准。
- 未实证项按 §5 三级判定（绿/黄/红）处置；**黄**（断言漏检）应优先考虑**扩断言正则**而非改译文。

## 6. 已知边界与误报声明（务必阅读）

- 断言语义**有界**：只靠特征词匹配，无法判断"该特征用得对不对、是不是最贴切"。

- **插入副词**：进行时/被动等若夹副词（`is profoundly changing`），正则已允许 0–1 个中间词；若插入更多修饰词可能漏检。

- **同义手段替换**：策略称"形合"，译文用其它合法连接方式（如冒号、破折号引注）可能未被 `CL-01` 特征词覆盖 → 视为"未实证"，人工确认后可绿灯。

- **不触发即审查**：未提及的学理手段不被检查，这是有意为之，减少噪音。

- **✅ 脚本双副本口径已统一（2026-09-21）**：此前工作区根目录与技能目录的两个 `_audit_scholar.py` **断言表不同源**（宽版含 CL-01~11；窄版 CL-01~10 且多项特征式偏窄），同一 158 套语料分别报 **1403 断言·0 未实证** 与 **1324 断言·62 未实证**。经对 62 处未实证逐条诊断，**确认全部为窄版漏检的假阳性**——译文均确有该机制，仅特征词未覆盖：`has become`／`has gone`（不规则过去分词）、`is widely regarded`／`are often performed`（副词插入）、`was widely planted`／`was written`（缺 `was/were` 支路）、`If … because …`／`but because`（连接词表缺 because/if）、`helps`（`\bhelp\b` 未含 -s）、`Using idioms`／`Learning chengyu`（动名词动词表缺失）、`to reduce`／`to ensure`（目的动词表过短）、`with the whole nation captivated`（`with + N + V-ed` 式）、`but`／`while` 中部出现等。**统一结论**：以**宽版为权威实现**（`SPEC_VERSION='v1.4'`）；§2 断言表已按宽版特征集修订并补入 CL-11；**全量 158 套在统一口径下复检为 1403 断言 · 0 未实证**，各批次登记数**无需变动**。**位置口径（2026-09-21 库归位后）**：现为**两处副本**——技能目录＝**权威副本**，真题侧库内 `_cet历年\管线\_audit_scholar.py`＝**本地调用副本**，二者**须同哈希**（原"工作区根目录／`_cet2026`"两处均已随库归位撤销）。
  - 附带修复：`--json <path>` 参数此前被丢弃（文档承诺但未实现），v1.4 已修复。
  - 验收口径：今后一切"0 未实证"结论**以 v1.4 统一版为唯一口径**，不再区分副本。
- **CL-04 覆盖缺口（已在 v1.4 统一版中消除）**：窄版曾未覆盖 `was/were + V-ed` 与不规则过去分词；v1.4 已补 `was|were` 支路与常见不规则形词表，故该缺口在统一口径下不再显现（历史记录保留以备追溯）。
- **冒号/破折号式形合**：以标点引注承载并列/说明（如 `have one thing in common: it …`）未被 `CL-01` 特征词覆盖 → 视为"未实证"；按 §5·附2 改写为「以冒号引注衔接」等**不含触发词**的表述，勿强行标"形合"。

## 7. L2·SB 句法框架子类登记规约

`语块 L2` 词块层下设两个子类，句法框架类名统一为 **L2·SB**（区别于词块 L2·PC）。

- **登记条件**：只登记**高频且教学意义明确**、可复用可迁移的句法骨架（如 `not only…but also`、`enable…to do`、`As…, 主句`、`To V…目的状语`）；无此类结构则**省略**，不硬凑、不名义化。
- **写法**：`骨架 + 槽位 + 本句实例`；槽位以 `_` 仅标可变成分。
- **禁则（不做全句通配误标）**：不得把整句原文挖空成一个"通配框架"，也不为罕见/一次性结构登记 SB。
- **与 CL 的关系**：SB 是**标注产物**，CL-01~11 是**核验依据**；CL 已覆盖对句法框架的可复现学理检验（CL-01 形合 / CL-05 使役 / CL-07 目的状语 / CL-03 分词等），SB **不新增学理范畴**。
- **导出视图**：需要"句法框架索引"时，从 `语块 L2` 中类名含 SB 的条目聚合导出即可；**标注本体保持 7 标签，不新增第 8 一级标签**。
- **排版说明**：单个句子允许将 L2·SB 单独成节展示，仅为可读性，数据归属仍是 `语块 L2`（类名 L2·SB）。
- **字段落位与可机检要求（2026-09-21 收官复检补记）**：
  1. 按《译文产出规约》§1 的句内字段序，末位字段应为 **`**语块 L2**：`**，句内同时含 **L2·PC 词块** 与（可选）**`**句法框架 SB**` 子节**。
  2. **词块类名须为纯类名**，用全角括号紧贴于该词块之后、并以 `；` 或 `。` 收尾（脚本 `CLS_PAT` 只认 `（PC）` 等 4 类之一，长度 1–6 字）：合法值 `（P）／（IE）／（PC）／（SB）`。**禁止**写成 `（PC，S1）`、`（PC，S1官方短语）` 一类复合形式——**级别信息一律归「来源」行或"〔S1〕"半角方括号**，否则会被判为 L2 类名不合法。
  3. **现状（2026-09-21 补登完成 · 并集收敛后终值）**：全量 158 套 **805 句**已执行 L2·PC 词块补登——`_backfill_l2.py` 以**双锚校验**（原文命中汉语锚 ∧ 译文命中词典英文候选）落盘，终值 **261 句 / 355 条词块**（类名分布 **PC 169 / SB 110 / P 73 / IE 3**），**覆盖率 32.4%**；含 `语块 L2` 行的句子由 **17 → 261**，此前"约 150 套未落词块行"的缺口由此闭合。全量 **0 处**非法类名、**0 处**未转义槽位；未命中的 **544 句**清单由 `_dump_nol2.py` 导出备查（多为确无词典可登记词块者）。**口径不变：仍以 `_backfill_l2.py` 作独立批任务执行（幂等并集收敛、只增不删），不在文本复检时零散补写**。
  4. 单套验收：`L2非法类名` 必须为 **0**；`L2语块` 计 0 时须在卡头注明"本卡仅登记 L2·SB 子节，L2·PC 见参考库"。
- **L2·PC 词块的登记口径：汉语识别 → 英文准入 → 汉英落笔（2026-09-21 补记）**：
  1. **识别与归类在汉语侧（键在汉）**：以汉语固定短语/文化词为对象（即《原文处理规约》§3⑥ 的识别产物），判断"**是不是**一个可复用词块""**归哪一类**""**跨卷是否同一词块**"。**汉语短语是本层的键**。
  2. **准入与匹配在英文侧（实证门槛）**：某词块**是否登记**，取决于该句**译文是否真的落实了它**——以词典（《固定短语参考库_累积》等）的**英文列回查该句译文，命中才登记**；译文未落地者**不登记**。此与学理自查同一纪律：**声称须有译文实证**，避免"汉语这边是固定短语、译文根本没实现"的**假登记**。
  3. **落笔为汉英并列条目**：写作 `汉语短语 英文实现（类名）`（键在汉、值在英），与《固定短语参考库》同构；可变成分用 `\_`（或 `_`）标槽位。例：`对…的敬意 respect for \_（PC）`。
  4. **一汉多译须列全候选**：本库体系为"**一汉多译**"（如 `乡村振兴` = `rural revitalization`／`rural vitalization` 并存）。**词典英文列未列全候选即会漏命中**，该句将被误判为"无 L2"——故维护词典时须**补齐并存候选**，而非只留首选；覆盖率瓶颈通常在**词典完备度**，不在回填工具。
  5. **四类名依据**：`P／IE／PC／SB` 采 **Nattinger & DeCarrico 1992** 语块四分类（`P` 多元词 / `IE` 习语式 / `PC` 短语构式 / `SB` 句型框架）；其中 `SB` 另按本节前述 L2·SB 规约，以独立子节 `**句法框架 SB**` 登记。
  6. **反例（禁）**：① 只凭汉语侧列词块、不问译文是否落地 → **假登记**；② 只凭英文偶然搭配、汉语侧并非固定短语 → **假匹配**；③ 把来源级别混写进类名括号（`（PC，S1）`）→ **类名非法**（见上条第 2 项）。
  7. **"双锚"修订（2026-09-21）**：首版**仅按英文单锚**匹配得 **289 句**，抽查即见**假匹配**——`养老服务/体系建设` 之英文候选含**单字 `system`**，误命中"汉朝…科举制度"句。故第 1、2 条**须合取为"双锚"**（原文 ∧ 译文），修订后先得 **182 句**，抽查 40 条无误。**纪律**：单看英文的**泛化触发**（`in China`／`system`／`become`／`since` 等）**一律不得单独登记**。
  8. **终值与两处工具缺陷修正（2026-09-21）**：① **召回缺陷**——英文候选编译时，助词形（`be/have/is/…`）的**可选组后误加一段 `\s+`**，使 `has been significantly improved`、`is one of the most …`、`be listed as` 一类候选**整条失配**（实为要求"两段空白"，且前置边界断言否掉唯一可行起点）；修正后新增 **62 句**命中。② **口径缺陷**——早期 182 行系上述有缺陷的正则产出，若只补新句将造成**同语料两套口径**；故改为**并集收敛**（`parse_existing_keys` 保留既有条目、只增不删，含手订条目），对已有行**扩写 11 句**。③ **遗留口径行** 1 句以 `--refresh-legacy` **就地升级**（其汉语侧先补入类词典：`一系列措施`／`显著改善`）。**终值：261 句 / 355 条（PC 169／SB 110／P 73／IE 3），覆盖率 32.4%**；全量复检 **1403 断言 · 0 未实证 · L2 非法类名 0**，`--dry` 重跑 **0 变更**（幂等）。实现要点：汉语键 `/` 表择一、`…` 表通配、括号注记剔除；落盘槽位统一 `\_`（含对 5 处手订行的一次性规范化）。
